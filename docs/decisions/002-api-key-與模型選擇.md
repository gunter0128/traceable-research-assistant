# 002：API key 由系統統一管理，生成模型可選、embedding 模型固定

日期：2026-10-14

## 背景

OpenAI key 目前放在環境變數（部署版存在 Secrets Manager），模型名稱寫死在 `core/openai_client.py`。我一開始覺得這樣對使用者不友善，應該要有地方讓使用者自己輸入 key、選模型。

## 考慮過的做法

1. **key 由系統管理，加上用量控管，生成模型可選**
2. **使用者自己帶 key（BYOK）**：不用我付錢，但 key 要加密存放（AWS KMS），絕對不能出現在 log，還要驗證 key 是否有效
3. **兩種都做**：最彈性，但範圍直接翻倍

## 決定

選 1。

這個系統的定位是企業內部可信任的知識問答。企業內部的系統不會叫員工自己貼 API key，key 由平台方統一管理，因為成本、資安（資料送到哪家廠商）和能用哪些模型都要集中控管。所以 key 放在環境變數本身是對的，那是營運方的 key，不是使用者的。

我原本覺得不方便，真正的問題其實是另外兩件事：

- **沒有用量控管。** 任何註冊的人都能無限次用我的 key，有人寫腳本洗請求，帳單就會爆。要記錄每個人的 token 用量和成本，超過上限就擋。這件事放進主線 C。
- **模型不能選。** 這點要做，但只開放生成模型，放進主線 B，順便讓評估可以比較不同模型。

## embedding 模型為什麼不能讓人選

生成模型每次問答時才呼叫，換了沒有副作用。embedding 模型不一樣：每份文件的向量都是用它算的，換一個模型之後，新問題的向量跟舊文件的向量不在同一個空間，相似度搜尋會變成亂搜，維度不同的話甚至直接報錯。換 embedding 模型等於整個 workspace 的文件要全部重新處理。所以它由系統統一指定，不開放切換。

## 代價

使用者不能用自己的 key。BYOK 本身是有料的資安題目，但它屬於加新功能，跟 001 的方向衝突，先不做。
