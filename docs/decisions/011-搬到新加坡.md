# 011：AWS 全部從雪梨搬到新加坡

日期：2026-10-16

## 背景

C1 做完結構化 log 之後，第一次能看到每一步花多久。同一份 30 頁的 PDF（51 段）在雲端處理要 14 秒，其中跟資料庫有關的步驟就佔了將近一半：

| 步驟 | 花多久 |
|---|---|
| 拿到工單 → 取得租約 | 4.0 秒 |
| 報平安 3 次 | 3.1 秒（1645 + 721 + 721 ms） |
| 存結果 | 2.4 秒 |

本機（台灣）同樣的報平安只要 210 ms。

## 找原因

在 worker 加了一個測量模式（手動呼叫時傳 `{"probe": true}`），在 Lambda 上直接量到資料庫的速度：

| 測量 | 雪梨 Lambda → 新加坡資料庫 |
|---|---|
| 網路來回一趟 | 170 ms |
| 新開一條連線 | 約 1100 ms（資料庫在休眠時 3155 ms） |
| 一個最小的 transaction | 720 ms |

所有的謎都對上了：
- 報平安一次要來回 4 趟（連線檢查、BEGIN、UPDATE、COMMIT），4 × 170 ≈ 720 ms
- 第一次報平安比較慢，是因為報平安用獨立的 session（008），要另外開一條新連線
- 取得租約前的 4 秒，是新開連線，加上 Neon 免費方案閒置 5 分鐘會休眠，要先叫醒

根本原因只有一個：每一趟來回都要 170 ms，而程式做每件事都要來回好幾趟，距離的代價被放大好幾倍。

當初選雪梨是因為原本要去澳洲，這個理由已經不存在了。使用者在台灣，資料庫在新加坡，只有 API 和 Lambda 在雪梨。從台灣量：到雪梨一趟約 220 ms，到新加坡約 50 ms。

## 考慮過的選項

| 選項 | 為什麼沒選 |
|---|---|
| 不搬，減少來回趟數 | 報平安 4 趟 → 2 趟，每份文件只省約 1 秒，其他步驟一樣慢。而且要拿掉連線檢查，Lambda 休眠後的失效連線就沒人處理 |
| 資料庫搬到雪梨 | 資料庫那段解決了，但使用者到 API 還是 220 ms；本機開發和測試會更慢 |
| 全部搬到台北 | 使用者到 API 只要 10 ms，但 Neon 沒有台北機房，API 到資料庫要 45 ms。使用者的一個動作只到 API 來回 1 趟，卻要到資料庫來回十幾趟，被放大的是 API 到資料庫這段，所以這段要最短 |
| 台北 + 資料庫改用 AWS RDS | 一個月多 15～30 美元，換到的只比新加坡快一點點 |

## 決定

AWS 的東西全部搬到新加坡（ap-southeast-1），跟資料庫放在同一個區域：ECR、ECS、SQS、兩個 Lambda、排程、S3、Secrets Manager、CloudWatch log group。IAM 是全球共用的，只把權限裡的資源從雪梨改成新加坡。

全部用 CLI 完成（雪梨那時候 ECS、排程是在主控台點的），步驟記在 `docs/deployment-commands.md`。

## 結果

同一份 PDF，搬家前（文件 30）和搬家後（文件 31）：

| | 雪梨 | 新加坡 |
|---|---|---|
| 資料庫來回一趟 | 170 ms | 3 ms |
| 新開一條連線 | 1100 ms | 28 ms |
| 報平安一次 | 721 ms | 9～11 ms |
| 取得租約 | 4019 ms | 44 ms |
| 存結果 | 2366 ms | 432 ms |
| 上傳請求 | 5.1 秒 | 1.2 秒 |
| 排隊 | 3.7 秒 | 0.03 秒 |
| 處理文件 | 14.0 秒 | 10.3 秒 |
| 上傳到完成 | 約 23 秒 | 約 11.5 秒 |

處理文件只少了 3.7 秒，是因為這次 OpenAI 比較慢（5.3 秒，上次 3.2 秒）。扣掉 OpenAI，我們自己能控制的部分從 10.8 秒降到 5.0 秒，剩下的主要是解析 PDF（4.1 秒，純計算）。

要注意：新加坡這次測試前剛跑過 probe，Lambda 和資料庫都是醒著的，雪梨那次資料庫可能在休眠，所以「取得租約」的差距有一部分是休眠造成的。但報平安、存結果這些每次都會發生的步驟，差距是確定的。

## 代價

- 搬家期間服務中斷約 1 小時（只有我在用）
- 一份文件現在在兩個區域都存過，雪梨的要記得刪乾淨
- Neon 的休眠問題沒有解決：閒置 5 分鐘後的第一個請求，還是要多等約 2 秒叫醒資料庫
