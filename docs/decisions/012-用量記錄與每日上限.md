# 012：用量記錄與每日上限

日期：2026-10-16

## 背景

002 決定 OpenAI key 由系統統一管理，當時就留了一個問題：任何人註冊之後都能無限次用我的 key。兩種情況會讓帳單爆掉：

- 有人寫程式不停發問、不停上傳
- 我們自己的程式出錯，例如重試寫錯變成無限重試

而且我完全不知道錢花在哪。OpenAI 的帳單只有總金額，看不出是誰、做了什麼花的。

先算過一次每個動作的成本：問一個問題約 0.0006 美元，處理一份 30 頁的論文約 0.0004 美元。一個人正常使用一天花不到 0.05 美元。所以上限的目的不是限制正常使用，是擋住不正常的情況。

## 決定

### 每次呼叫 OpenAI 都記一筆，存在資料庫

OpenAI 每次回應都會附上這次用了多少 token，乘上價格就是成本。每次成功呼叫就記一筆：誰、做什麼（問答 / 處理文件）、哪個模型、多少 token、多少錢。

存在資料庫的新資料表 `usage_records`，不是只寫在 log：每次問答前都要查「今天用了多少」，資料庫一個 SUM 查詢就好；如果存在 log，每次都要去 CloudWatch 查，又慢又貴。用量也會順便寫進 log（`openai_usage` 事件），在 CloudWatch 統計時不用連資料庫。

幾個細節：
- 只有成功的呼叫才記：失敗的請求 OpenAI 不收錢
- 錢用精確小數（`Numeric`）存，不用 float：float 是近似值，加總很多筆之後誤差會累積
- 處理文件的用量算在上傳的人（workspace 的主人）身上
- 處理文件的用量用另一個 session 立刻寫入，跟報平安一樣：處理失敗時處理用的 session 會 rollback，但錢已經花掉了，紀錄不能跟著消失
- 問答的用量先收集起來，最後一起寫入；生成答案失敗的話，問題轉向量已經花掉的錢還是會記
- 價格寫在 `openai_client.py`，OpenAI 調價時要跟著改

### 兩層上限：每人每天 0.5 美元、全系統每天 5 美元

- 每人每天 0.5 美元，大約是 800 個問題，正常使用碰不到
- 全系統每天 5 美元：任何人都能註冊，只限制每人的話，註冊 100 個帳號就繞過了。這是最後一道防線，保證一天的帳單最多就這麼多
- 「今天」用台灣時間算，使用者在台灣，「明天再試」就是台灣的半夜 12 點之後

### 開始之前檢查，開始了就做完

問答、上傳、重試「開始之前」檢查今天的用量。還沒到上限就放行，**這一次會完整做完**，就算做完之後超過了也一樣；下一次才擋，回 429「今日用量已達上限，明天再試」（全系統到上限是另一個訊息）。

```
今天已用 0.4995 → 問問題：開始前 < 0.5，放行，完整回答 → 已用 0.5001
                                              └→ 前端馬上顯示「今日用量已達上限」
             → 再問：開始前 ≥ 0.5，擋下來
```

我不想讓做到一半的事情被中斷：上傳到一半被擋，使用者會看到一份處理失敗的文件，已經花掉的錢也白花了。跨過上限的那一次，前端會在問答完、文件處理完之後查一次用量（`GET /usage/today`），到上限了就馬上顯示提示，使用者當下就知道，不用等到下一次被擋才發現。

代價是實際用量最多會超過上限「一次動作」的量。最貴的情況是剛好卡在邊緣時處理一份 300 頁的文件，約 0.004 美元，可以忽略。

## 沒有做的

- 註冊本身沒有限制（例如 email 驗證、邀請制）。全系統上限讓大量註冊最多只能花掉一天 5 美元，現在夠用
- 上限是寫在程式裡的常數，不能針對不同使用者設不同上限
- 沒有讓使用者看到自己的用量明細，只有「到上限了沒」
