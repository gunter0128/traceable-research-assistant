# 017：評估方法，以及怎麼避免把 prompt 改成「背考卷」

日期：2026-10-20

## 背景

016 做好了青嶼科技的知識庫和 58 題。接下來要決定兩件事：怎麼打分數，以及怎麼用分數改系統。

第二件事是我自己的顧慮：之後要改 prompt，如果是看著這 58 題的錯誤來改，很可能只是讓系統更會回答「青嶼科技」的文件。但真正的使用者是上傳自己 PDF 的人，可能是企業員工，也可能是學校老師或一般人。這樣改分數會變好看，對其他使用者卻沒有幫助，甚至會變差。這就是過度擬合。

## 決定

### 評分：檢索用程式判斷，回答用 AI 評審對清單

| 看什麼 | 怎麼判斷 |
|---|---|
| 檢索完整（Full Hit，沿用我論文的指標） | 程式判斷：這題應該引用的文件，是不是全部出現在系統搜到的段落裡 |
| 重點涵蓋 | gpt-4o 評審逐項判斷：「一定要提到的事實」有沒有提到 |
| 誤用 | gpt-4o 評審判斷：「出現就算錯的說法」有沒有出現，例如把正職的特休套到實習生身上 |
| 拒答正確 | gpt-4o 評審判斷：該說找不到的有沒有說、不該說的有沒有亂說 |
| 全對 | 重點全提到、沒有誤用、拒答正確 |

評審設成 temperature 0，只對清單逐項判斷，不打 1～10 分的整體分數。整體分數看不出錯在哪一項，清單可以逐項回頭查。評審會不會判錯：基準跑完後抽了 10 題，由 Claude 逐題對照系統的回答和標準答案，10 題評審都判對。

答錯的題目再分兩種，這也是我論文用的雙層分析：

- **沒搜到（取得層）**：該用的文件根本沒搜到，要改的是檢索（例如多搜幾段）
- **搜到了還答錯（使用層）**：文件搜到了，但模型讀錯、用錯，要改的是給模型的資料和 prompt

每次評估跑 2 輪，因為模型的回答每次會有一點不同，兩輪差很多代表那個數字不可靠。

評估用的是用完就丟的臨時資料庫（Docker），絕對不碰正式資料庫。文件和問題走的是跟線上同一份處理程式碼（`document_service`、`qa_service`），測到的就是線上的行為。

### 防止過度擬合：三道防線

1. **prompt 只寫通用的閱讀原則**。每加一條規則都要問：這條套到租屋合約、學校規章、論文上也成立嗎？不成立就不加。prompt 裡不能出現「年資」「職級」「正職」這種只屬於企業文件的詞。
2. **題目分成練習題和考試題**。58 題裡，每種題型隨機抽 30% 當考試題，共 17 題；剩下 41 題是練習題。隨機種子固定，重跑也是同一批。改進的過程中只看練習題錯在哪，考試題的內容不看，全部改完才跑一次。
3. **第二個領域：虛構的國小**。我有一位使用者是國小老師，所以第二個領域選學校，設計一間虛構的「澄溪國小」：8 份文件、21 題，問的人有老師也有家長。陷阱和企業版同類：依身分不同、新舊版本、內文和修正紀錄衝突、只改一部分的公告、分校規定優先。文件格式刻意不同，用學校公文的條列式（一、（一））、民國年、公告格式，這樣才測得出 prompt 是不是只看得懂企業文件的寫法。這套整套都當考試題。

判斷方式：**練習題進步了、考試題和學校題沒有進步，代表是在背考卷，那個改動要退回。**

### 基準（改進之前的成績）

| 題目 | 全對（2 輪） | 最差的題型 |
|---|---|---|
| 企業全部 58 題 | 60% / 57% | 範圍陷阱 25% / 0% |
| 企業練習題 41 題 | 58% / 54% | 範圍陷阱 17% / 0% |
| 學校 21 題 | 76% / 76% | 範圍陷阱 0% / 0% |

兩個領域最差的都是範圍陷阱，而且錯的方式一樣：文件寫的是「這條規定不適用某些人」，系統卻直接回答「文件中找不到相關資訊」。企業 8 題裡有 6～8 題、學校 3 題全部都是這樣錯。這代表問題出在系統本身（prompt 太嚴，看到「不適用」就當成找不到），不是企業文件特有的現象，所以改進的方向應該是通用的。

### 最終驗證（A、B、文件不編號、維持 5 段都做完之後）

改進的過程中沒看過內容的兩套題目，第一次拿來跑：

| 題目 | 基準全對 | 最終全對 | 進步 |
|---|---|---|---|
| 企業練習題（41 題，改進時看的） | 58% / 54% | 78% / 76% | 約 +21% |
| 企業考試題（17 題，沒看過） | 65% / 65% | 71% / 71% | 約 +6%（1 題） |
| 學校（21 題，別的領域） | 76% / 76% | 90% / 86% | 約 +12% |

- **改進最主要的目標有效，而且換題目、換領域都成立**：範圍陷阱在考試題從 50% / 0% 變成 100% / 100%，在學校從 0% / 0% 變成 67% / 67%
- **考試題的進步比練習題小很多**：一部分是因為考試題的基準本來就比較高（65%），能進步的空間小；但也代表練習題上的 +21%，有一部分可能是只對練習題有效，或是隨機的運氣。要說「系統進步了多少」，應該用考試題和學校題的數字，不是練習題的
- **新出現的風險**：考試題的「沒有答案」題，第 1 輪有一題沒說找不到，自己編了答案。B 放寬了「找不到」的條件，模型更敢回答，這是當初就預期的代價（019），要持續注意

## 代價

- 評審也是 AI，還是可能判錯；目前只抽查了 10 題，而且是 Claude 抽查的，我自己沒有逐題看過
- 題數少：考試題 17 題、學校 21 題，一題的差異就是 5% 左右，所以要看兩輪，也不能只看小數點的差距
- 學校知識庫很小（16 段），搜前 5 段就搜到快三分之一，學校題幾乎測不到檢索，主要測的是模型讀得對不對
- 兩套文件都是我跟 Claude 寫的，寫作風格可能還是比真實文件整齊、相近。真實文件要等那位國小老師實際使用時再測
- 每次評估約 0.3～0.7 美元
