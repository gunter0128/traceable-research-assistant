# 018：問答時給模型看「段落出自哪份文件」和今天的日期

日期：2026-10-20

## 背景

B4 的基準評估（017）發現一個問題：文件切成段落之後，一段文字常常看不出是哪份文件、哪個版本。

例如 2026 年版員工手冊有 995 個字，切成 3 段，「生效日期：2026 年 1 月 1 日」只在第 0 段，特休的規定在第 1 段。員工問特休時，2025 和 2026 年版的第 1 段都會被搜到。兩段幾乎一模一樣，只差在天數，模型看不出哪一段是現行的，只能猜。

另外，系統從來沒有告訴模型今天是幾號。模型以為的「現在」是它的訓練時間，所以遇到「10 月起調整」這種寫法，沒辦法判斷調整生效了沒有。

## 決定

### 每份文件附上檔名和開頭約 200 字

| 選項 | 為什麼沒選 / 為什麼選 |
|---|---|
| 只附檔名 | 使用者的檔名常常是「scan001.pdf」「下載 (3).pdf」，靠不住 |
| **檔名 + 文件開頭（選這個）** | 規章、公告、合約的標題和日期通常就寫在開頭，這是通用的寫法。開頭直接給模型讀，不用自己解析日期：民國年、西元年、學年度各種寫法，模型都讀得懂。不用改資料表，已經上傳的文件馬上適用 |
| 上傳時請 AI 讀出標題、生效日期、適用對象，存進資料表 | 要改資料表，舊文件要補做；AI 可能讀錯；論文這類文件根本沒有生效日期。等以後要在畫面上顯示生效日期時再考慮 |

開頭取的是每份文件第 0 段的前 200 字。使用者上傳時不用多填任何資料。

### 同一份文件的段落放在一起

給模型的資料改成先列文件，再列這份文件被搜到的段落。文件的先後照各自最相關的那一段排，段落照原文的順序排。這樣「這兩段出自不同版本」一眼就看得出來。段落編號 [1] [2] 跨文件連續編，引用的順序也改成一樣，以後做逐句引用時才對得起來。

### 告訴模型今天的日期

線上用台灣當天的日期。評估時固定成知識庫設定的「現在」（2026-10-20），分數才不會因為哪天跑評估而變。

### 這次不動的部分

prompt 不改（那是改進 B），搜前 5 段也不改（那是改進 C）。一次只改一件事，才知道進步是哪一項帶來的。

## 結果（企業練習題 41 題，各跑 2 輪）

| | 基準 | 改進 A |
|---|---|---|
| 全對 | 58% / 54% | 61% / 66% |
| 誤用 | 7% / 2% | 0% / 2% |
| 重點涵蓋 | 62% / 61% | 74% / 74% |
| 拒答正確 | 78% / 76% | 80% / 85% |

各題型的變化：

- **身分題**：57% / 43% → 71% / 71%
- **跨文件題**：75% / 75% → 75% / 100%
- **條件題**：40% / 40% → 40% / 50%。「特休有幾天」就是上面那個 2025 / 2026 年版的例子，從兩輪都錯變成兩輪都對
- **版本題**：50% / 50%，沒變。答錯的兩題都不是 A 能修的。「最晚幾點到公司」是 2026 年版根本沒搜到，只搜到 2025 年版（檢索問題，留給改進 C）。「業務部遠距」答對了，但沒說生效日期（要靠 prompt 要求，留給改進 B）
- **範圍陷阱**：17% / 0% → 17% / 17%，跟預期一樣沒改善。這是 prompt 太嚴的問題，留給改進 B

## 代價

- 每次問答多一次資料庫查詢（查這幾份文件的第 0 段），只要幾毫秒
- 送給模型的字多了約 1,000 字，gpt-4o-mini 每題多花不到 0.0002 美元
- 開頭沒寫標題和日期的文件（掃描檔、筆記），這個改動幫不上忙
- 200 字是估出來的：企業和學校文件的標題和日期都在前 100 字內，但論文這種開頭是作者和摘要的文件，200 字可能讀不到有用的資訊
- 第 0 段本身也被搜到時，開頭會重複出現一次，浪費一點字數
