# 025：跟 OpenAI 現成的文件問答服務比較

日期：2026-10-23

## 背景

跟學長討論專案時被點出一個問題：ChatGPT、NotebookLM 這類工具本來就能上傳文件、附上出處，甚至可以上網找資料。那這個系統有什麼用？

到目前為止，評估都是拿系統跟「一般的 RAG」（基準）比。進步雖然明顯，但沒有跟市面上真正的產品比過，答不出「為什麼不直接用 ChatGPT 就好」。

## 怎麼比

用 OpenAI 現成的 file search 服務（Responses API 搭配 file_search 工具），跟 ChatGPT 上傳檔案的功能是同一類：

- 同樣的 PDF（企業 18 份、學校 8 份），切段、轉向量都交給 OpenAI 用它預設的方式做
- 同樣的回答模型（gpt-4o）
- 同樣的題目：企業的考試題 17 題、學校 21 題，都是改進的過程中沒看過的
- 同樣的評審和評分標準（`eval/run.py` 的 `score`）
- 給模型的指示只有一句「根據使用者提供的文件回答問題」和今天的日期，不放我們的回答原則，因為要比的是「直接拿現成服務來用」的樣子

程式在 `eval/openai_baseline.py`。比完就把上傳到 OpenAI 的檔案刪掉。

NotebookLM 沒有程式介面，沒有比。手動在網頁上問，每次的結果不同，也很難用同一套標準打分。

## 結果（各跑 2 輪）

| | OpenAI file search | 我們的系統 |
|---|---|---|
| 企業考試題全對 | 82% / 71% | 76% / 82% |
| 學校題全對 | 86% / 86% | 95% / 95% |
| 範圍陷阱（兩套合計 10 次） | 80% | 100% |
| 版本題 | 企業 0%、學校 100% | 企業 0%、學校 100% |
| 檢索完整 | 100% | 87%～100% |
| 平均回答時間 | 4.0～4.7 秒 | 1.6～1.7 秒 |

## 結論

- **企業題差不多，學校題我們好約 9%**。OpenAI 答錯的題目不是套錯規定（誤用 0%），而是**答得太精簡、漏了條件**：問導護要輪幾週，只答「導師 1 週」，沒提科任 2 週、主任和組長免輪值；鐘點代課老師問請假，答了該怎麼做，卻沒明說「請假規定不適用你」；分校的校外教學漏了交通費由學校補助。我們的回答原則（019）要求列出各種情況、不適用也要說，差距就在這裡
- **回答速度快約 2.5 倍**
- **兩邊的版本題都答錯**（企業的 2 題）：這是共同的弱點
- **OpenAI 的檢索完整是 100%，因為知識庫太小**。企業只有 18 份文件、38 段，OpenAI 的服務每次會撈很多段，幾乎等於全部看過一遍。真實的組織有幾百、幾千份文件，不可能每次都全部看，到那時「搜得準不準」才會拉開差距

所以這次比較的意義是：

1. 在小型知識庫上，**回答原則**是目前唯一明顯的優勢，而且主要在學校這種格式不同的文件上才看得出來
2. **現在的評估考不出檢索方法的差別**。接下來要做的規劃器（先分析問題要查哪些證據，再分別搜尋）是在改善檢索，要量出它的效果，評估用的知識庫必須先擴大：更多文件、更多舊版本、更多看起來相關但其實不適用的規定

## 代價

- 只比了 OpenAI 的服務，沒有比 NotebookLM 和其他產品
- 題數少（17 + 21 題），企業題兩輪之間的差距（71% 和 82%）比兩個系統之間的差距還大
- 給 OpenAI 服務的指示很簡單。如果也寫一套詳細的回答原則給它，差距可能會縮小；這代表優勢在「怎麼要求模型回答」，而不是不可取代的技術
- 沒有比較成本：OpenAI 的服務每題會送很多段給模型，費用應該比我們高，但這次沒有量
