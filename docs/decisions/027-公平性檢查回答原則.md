# 027：公平性檢查：OpenAI 也拿到同樣的回答原則

日期：2026-10-23

## 背景

跟 OpenAI 的 file search 比較時（025、026），我們的系統一直在「回答」上贏：考試題高約 9 個百分點、學校題高約 12 個百分點。但比較並不完全公平：我們的模型拿到 7 條回答原則（019），OpenAI 只拿到一句「根據使用者提供的文件回答問題」。

這樣比會被質疑：贏的是系統設計，還是只是 prompt 寫得比較詳細？025 的「代價」也寫了這個疑慮。要回答「為什麼不直接用 ChatGPT」，這個問題一定要先釐清。

## 怎麼比

跟 026 一樣的知識庫（企業 78 份、學校 41 份）、題目、評審，唯一的差別是：給 OpenAI 的指示換成我們系統的 7 條回答原則（`openai_client.ANSWER_RULES`）加上今天日期，跟我們的系統一字不差。

`eval/openai_baseline.py --rules`，企業考試題 17 題和學校 21 題，各跑 2 輪。

## 結果

| | 企業考試題全對 | 學校題全對 | 平均回答時間 |
|---|---|---|---|
| OpenAI，原本的一句指示（026） | 59% / 65% | 71% / 71% | 4.5～5.1 秒 |
| **OpenAI，給同樣的 7 條原則** | **65% / 71%** | **76% / 81%** | 4.5～4.7 秒 |
| 我們的系統（026） | 71% / 71% | 90% / 76% | 1.7～1.8 秒 |

- 給了原則之後，OpenAI 兩套題目都進步約 6～7 個百分點
- 剩下的差距：企業平均 71% 對 68%，學校平均 83% 對 79%，換算成題數**大約差 1 題**
- 一題就佔 5～6 個百分點，我們自己兩輪之間在學校題就差了 14 個百分點，**這個差距在隨機波動的範圍內**

## 結論

**回答上的優勢，大部分來自回答原則，不是系統的其他設計。**

這個結果有兩面：

- **不利的一面**：回答原則是一段文字，誰都可以抄。只靠它，答不了「為什麼不直接用 ChatGPT」
- **有利的一面**：同一套原則放到另一個系統（OpenAI 的 file search）上也有效。019 規定每一條都要是通用的閱讀原則、不放任何領域的詞，這次是一個證據：原則不是只對我們的檢索流程或這兩套題目有效

所以系統真正還站得住的差別是：

| | 我們的系統 | OpenAI file search |
|---|---|---|
| 回答時間 | 1.7～1.8 秒 | 4.5～5.1 秒 |
| 每題送給模型的量 | 5 段，約 2,600 token | 約 20 段，約 11,700 token（3 題實測） |
| 檢索完整 | 企業考試題 87%、學校 94% | 企業考試題 87～93%、學校 100% |
| 可以改的地方 | 切段、搜尋、規劃、回答都能自己改、自己量 | 只能改指示 |

也就是說，**在「用少量段落、很快地回答」這個條件下，檢索準不準就是勝負關鍵**。OpenAI 靠一次看很多段來補檢索，我們做不到也不想這樣做（慢、貴）。接下來的規劃器（028）要做的，就是用少量的段落把檢索拉上來。

## 代價

- 題數少：17 + 21 題，差 1 題就差 5～6 個百分點，這次的差距無法說誰比較好，只能說「差不多」
- OpenAI 的 file search 內部怎麼切段、怎麼排序、送幾段給模型，我們看不到也改不了，只能比整體的結果
- 費用只用 3 題實測過送給模型的 token 數，沒有完整算過每題的成本
- 回答原則是在我們的系統上調出來的（019），OpenAI 拿到的是「別人調好的版本」，如果針對它的檢索方式再調，可能還會更好
