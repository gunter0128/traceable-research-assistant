# 028：搜尋前的規劃

日期：2026-10-23

## 背景

027 的結論是：在「只給模型少量段落」的條件下，檢索準不準是勝負關鍵。擴大知識庫之後（026），練習題的檢索完整只有 65%，答錯的題目大多是該用的文件沒搜到。

我的論文（ER-RAG）處理的是同一個問題：先讓模型分析「回答這題需要哪些證據」，再分別去搜，每一種證據都保留名額，不會被別的擠掉。這次把這個想法搬到規章問答上試試看。

## 試了哪些做法

原本的問題一定會搜，規劃出來的搜尋接在後面。每一筆搜尋各自搜，再**輪流合併**：先拿每一筆的第 1 名，再拿第 2 名……拿滿為止，重複的跳過。合併後的段數跟不規劃時一樣，給模型看的量不變。規劃都用 gpt-4o-mini、temperature 0，最多 4 筆。

| 做法 | 規劃怎麼寫 |
|---|---|
| none | 不規劃（線上現在的做法） |
| rewrite | 自由改寫成 1～4 句搜尋句子（OpenAI 的 file search 也是這樣做） |
| checklist | 照四種常見的資料逐項判斷要不要找：主要規定、例外與不適用、新版與修訂、補充規定 |
| catalog | checklist 再加上**文件清單**（檔名和開頭 100 個字），可以指定「去哪一份文件找」 |

catalog 是看完前三種的結果才加的。沒搜到的題目有一個共同點：缺的常常是「講某一群人、某個地點的另一份文件」，例如問特休要另外查約聘人員管理辦法、問加班餐費要另外查台中分公司補充規定。只看問題的規劃，不知道有這些文件，就想不到要去查。

程式：`openai_client.plan_queries`、`qa_service._plan / _search / _merge_round_robin`。只比檢索的篩選用 `eval/retrieval.py`（不生成答案、不請評審，很便宜），留下來的再用 `eval/run.py --planner` 跑完整評估。

## 結果

### 只比檢索（練習題，有答案的 37 題）

| 做法 | 5 段 | 8 段 | 規劃秒數 |
|---|---|---|---|
| none | 65% | 68% | — |
| rewrite | 73% | 73% | 1.3 |
| checklist | 70% | 70% | 1.5 |
| catalog | 73% | **78%** | 1.8 |

### 完整評估（各 2 輪）

| | 練習題 41 題 | 考試題 17 題 | 學校 21 題 | 回答時間 |
|---|---|---|---|---|
| 檢索完整：none 5 段 / none 8 段 / catalog 8 段 | 65 / 68 / 80% | 87 / 87 / 90% | 94 / 100 / 97% | |
| 全對：none，5 段（線上） | 71% / 63% | 71% / 71% | 90% / 76% | 1.7 秒 |
| 全對：none，8 段 | 78% / 68% | 76% / 65% | 86% / 81% | 2.0 秒 |
| 全對：rewrite，8 段 | 71% / 63% | — | — | 3.7 秒 |
| 全對：catalog，5 段 | 73% / 68% | — | — | 4.0 秒 |
| 全對：catalog，8 段 | 68% / 78% | 71% / 59% | 90% / 81% | 3.9 秒 |

（catalog 的檢索完整是兩輪的平均：規劃的結果每次不完全一樣。）

**檢索變好了，答案沒有變好。** catalog 在最難的練習題上多找到 15 個百分點的文件，但「全對」跟不規劃差不多，差距都在隨機波動內，回答時間卻多了約 2 秒。

## 為什麼答案沒有變好

把 catalog（8 段）「該用的文件都搜到了、還是答錯」的 18 題逐題分類：

| 錯誤類型 | 題數 | 例子 |
|---|---|---|
| **把不適用的文件當答案** | 7 | 子公司的加班上限 40 小時、2027 年才生效的住宿上限、111 學年度舊版的帶隊比例 |
| 漏了條件或例外 | 6 | 沒提試用期不能遠距、主任和組長免輪值導護 |
| 計算、合併出錯 | 2 | 把地區彈性假加進特休，算成 15 天 |
| 評審太看字面 | 3 | 意思對，但沒寫出「準用」「一般職」 |

用論文的雙層分析來看：規劃器解決的是**取得層**（沒搜到），但現在的瓶頸已經移到**使用層**（搜到了卻用錯）。最大宗是「分不出哪份文件現在對問的人有效」，而規劃器刻意去找例外和新版，反而會把子公司的規定、舊版文件一起帶進來。

## 決定

- **線上維持不規劃、5 段**（`qa_service.PLANNER = "none"`）。答案沒有變好，不值得多等 2 秒
- 規劃器的程式留著，當評估的選項。預設關閉時，搜尋的結果跟原本一模一樣
- 下一步改做**適用性判斷**：回答之前，先判斷每份搜到的文件對問的人現在是否有效（現行、舊版、還沒生效、草案、別的組織），標在資料上再給模型。這是量出來的最大錯誤來源
- 原本打算把規劃器蒸餾成自己訓練的小模型（MLOps），改成以適用性判斷為訓練目標：它直接針對瓶頸，而且是範圍明確的分類問題，適合小模型，也能單獨量準確率

## 代價

- catalog 的提示是看練習題答錯的題目設計的，有貼合練習題的風險；考試題和學校題本來檢索就接近滿分，驗證不出它在更難的知識庫上的效果
- 文件清單最多給 200 份，更大的知識庫要另外想辦法（例如先依標題篩選）
- 規劃用 temperature 0，但結果不是每次都一樣：同一套學校題，兩輪的檢索完整分別是 100% 和 94%
- 「評審太看字面」的 3 題，代表評分本身也有誤差，之後可以抽樣人工檢查評審的判斷
