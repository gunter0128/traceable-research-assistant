# 034：企業內部版，以及訓練自己的回答模型

日期：2026-10-24

## 背景

033 量完之後，規劃器模型不值得訓練。回頭看需求：很多企業的文件是機密，**不能送到外部的 AI 服務**（例如半導體公司的內部規章、製程文件）。現在的系統每次回答都把文件內容送到 OpenAI，這些企業根本不能用。

所以 MLOps 的方向改成：**在內部的 GPU 上跑開源模型，資料完全不出公司**；需要的話，再訓練它。

## 先量：開源模型不訓練的話差多少

青嶼科技、勞動法規各 70 題（練習題 + 考試題全部），找 5 段、固定長度切段，各 2 輪。Qwen3.5-9B 用 vLLM 架在實驗室的一張 RTX 3090（24GB）上，關掉思考模式。

指標：

- **全對**：重點全提到、沒說錯、該拒答的有拒答
- **引用完整**：答案的 [1][2] 標到了所有該引用的文件；沒有答案的題目要一個都沒標。題目列了兩份出處時兩份都要標，所以偏嚴，但對每個模型都一樣
- **誤用**：說出了「不能說」的錯誤內容，例如把子公司的規定當答案
- **秒數**：每題從轉向量、搜尋到回答完的時間（不含評審）

| 回答模型 | 全對：青嶼科技 | 全對：勞動法規 | 全對：平均 | 引用完整 | 誤用 | 秒數 |
|---|---|---|---|---|---|---|
| gpt-4o（線上） | 73% / 74% | 63% / 70% | 70.0% | 66% | 6% | 1.7～2.0 |
| gpt-4o-mini | 67% / 67% | 63% / 69% | 66.5% | 60% | 10% | 1.7～1.8 |
| Qwen3.5-9B（不訓練） | 79% / 77% | 69% / 69% | 73.5% | 55% | 9% | 7.2～8.4 |

（140 題、2 輪平均，全對的隨機誤差粗估 ±3 分。）

- **正確率三個模型差不多**：都在 66～74% 之間。剩下的錯誤（沒讀懂「準用第 X 條」、沒找到需要的段落）對每個模型都難，瓶頸不在模型大小
- **Qwen 的問題在說話習慣**：回答平均 348 字（gpt-4o 102 字），一半以上用粗體和條列，會把現行版、廢止的舊版、子公司全部列一遍；句子後面比較少標出處；偶爾出現簡體字、亂碼，也偶爾讀錯數字（例如把「10 年以上」讀成「13 年以上」）
- **慢 4 倍**：主要因為回答長，加上一張遊戲顯卡、為了塞進記憶體關掉了加速功能

## 決定

### 一、一份程式碼，兩種部署

| | 公開展示版 | 企業內部版 |
|---|---|---|
| 放在哪 | AWS（Lambda、CloudFront，現在這套） | 公司內部的一台 GPU 主機 |
| 轉向量 | OpenAI | 本機的開源模型 |
| 回答 | gpt-4o | 訓練過的 Qwen3.5-9B |
| 部署 | GitHub Actions | docker-compose：資料庫、檔案服務（MinIO，用法跟 S3 一樣）、API、前端、回答模型、轉向量模型 |

雲上的系統不直接接實驗室的 GPU：實驗室的機器在內部網路，開放出去有資安風險，共用的機器也不能 24 小時給線上系統用；而且跟「資料不出公司」的目的矛盾。不租 AWS 的 GPU 主機：一個月要 700 美元以上。

回答的服務已經可以設定（`openai_client.use_answer_endpoint`）；轉向量之後照同樣的方式改。

### 二、訓練目標：改說話習慣，不追求提高正確率

正確率已經跟 gpt-4o 差不多，問題在回答的方式；而且這次用的訓練方式（只訓練一小組轉接器的參數）擅長改「習慣」，不擅長加「能力」。

| 目標 | 現在 | 上線門檻 |
|---|---|---|
| 每句話標出處 | 引用完整 55% | ≥ 66%（gpt-4o 的水準） |
| 先給結論、精簡 | 348 字 | ≤ 150 字 |
| 舊版、子公司只用一句話說明為什麼不適用，不完整列出 | 誤用 9% | ≤ 6% |
| 只用繁體中文、不用粗體 | 偶爾出現簡體字、亂碼 | 不出現 |
| **正確率不能下降** | 73.5% | ≥ 72%（扣掉隨機誤差） |

門檻在訓練之前就訂好，五項都達到才上線。不期待訓練修好「讀錯數字」。

### 三、訓練資料

- **絕對不用評估的三套知識庫**，避免模型背答案
- **跟實際使用時長得一模一樣**：用系統自己的流程對訓練用的文件真的去搜尋，組成跟線上一樣的輸入（回答原則 + 搜到的段落 + 問題），所以也會有「搜不到答案」的例子
- **文件**：其他公開法規（排除所有勞動相關的法規）為主，加 1 個新的虛構組織（可以設計子公司、草案這類陷阱）
- **示範答案**：先試 Qwen 自己開思考模式慢慢想，再把好的答案拿來教不思考的版本（不用外部服務，跟「資料不出公司」一致）。前提是思考模式的答案真的比較好，先驗證；不夠好再考慮 gpt-4o
- **只留通過檢查的**：答案正確（對標準答案和評審）、每句有出處、標的段落裡真的有那個數字、長度合理
- 數量約 1,000～3,000 筆

### 四、訓練方法

QLoRA：主模型壓縮成 4-bit 放著不動，只訓練一小組轉接器的參數（約原本的 1%），一張 3090 就跑得動。上線時用 vLLM 載入轉接器；每個版本的轉接器都有版本號和評估結果，可以退回上一版。超參數（學習率、轉接器大小、訓練幾輪）在練習題上比較，考試題只在最後確認。

### 五、轉向量也換成本機的模型

只換回答的話，文件和問題還是會送到 OpenAI 轉向量，「資料不出公司」做不到。換了轉向量模型，找到的段落就會不一樣，所以：

- **先決定轉向量模型，再產生訓練資料**：訓練時看到的段落要跟實際使用時一樣
- 只比檢索就能挑（不用生成答案、不用評審），很便宜
- 換了之後，基準數字和 gpt-4o 對 Qwen 的比較要重跑；評估方法、題目、之前實驗的結論不用重做

## 階段

| 階段 | 做什麼 | 喊停的條件 |
|---|---|---|
| 0. 前置測試 | ① 挑本機的轉向量模型（只比檢索）② 測 Qwen 思考模式的品質和速度 | 本機轉向量模型比 OpenAI 差很多 → 先處理檢索 |
| 1. 小規模試做 | 約 300 筆資料，訓練一次，在練習題上看習慣有沒有變 | 引用和長度都沒改善 → 檢討資料或方法 |
| 2. 擴大 | 約 2,000 筆，調參數，過上線門檻 | 過不了 → 不上線，記錄原因 |
| 3. 內部部署 | docker-compose、加快速度、監控、在實驗室實際部署一次 | — |
| 4. 整理 | ADR、架構文件、README | — |

## 代價

- 企業內部版沒辦法讓任何人上網試用，只能用影片和數據證明
- 訓練後預估每題 3～4 秒，還是比 gpt-4o 慢；這是一張遊戲顯卡對上 OpenAI 的資料中心，資料不出公司要付的代價
- 實驗室的機器是共用的：硬碟只剩約 30GB，GPU 也可能被別人用；裝 NVIDIA Container Toolkit 要重啟 Docker，會影響別人的容器，要先問過
- 訓練資料大部分是法律，風格跟公司規章不同，訓練出來的習慣不一定完全適用於公司規章，要在青嶼科技的題目上確認

## 後續（2026-10-25）

- 「偶爾出現簡體字、亂碼」幾乎都是抽字設定造成的：之前接 Qwen 用的是 vLLM 的預設，照模型說明的建議設定重量後，簡體字從 13% 降到 0.4%、誤用降到 6%，見 036
- 上線門檻改了：拿掉「≤ 150 字」，改成「去掉雜訊、保留資訊」，加上重點涵蓋不能下降；示範答案確定用 Qwen 思考模式，見 036
- 轉向量模型選了 Qwen3-Embedding-0.6B，見 035
