# 037：系統可以設定接 OpenAI 或本機的模型

日期：2026-10-25

## 背景

034 決定企業內部版的轉向量、回答都用本機的模型，資料不出公司；035、036 選好了模型（Qwen3-Embedding-0.6B、Qwen3.5-9B 不思考）。原本的規劃是先訓練、最後才部署，現在改成**先讓系統接上本機模型、在實驗室架起來，再訓練**：

- 產生訓練資料時，本來就要用「接上本機模型的系統」搜段落，這一步一定要先做
- 先做完，「資料不出公司」的系統就已經能展示；訓練是在這之上的改善

這份是第一步：同一份程式碼，用設定決定接 OpenAI 還是本機的模型。

## 決定

### 一、用設定切換，沒設定就是 OpenAI

| 設定（環境變數） | 公開展示版 | 企業內部版 |
|---|---|---|
| `EMBEDDING_BASE_URL` | 不設（OpenAI） | 內部的轉向量服務 |
| `EMBEDDING_MODEL` | text-embedding-3-small | Qwen3-Embedding-0.6B |
| `EMBEDDING_DIMENSION` | 1536 | 1024 |
| `EMBEDDING_QUERY_PREFIX` | 不設 | 模型要求加在問題前面的任務說明 |
| `ANSWER_BASE_URL` | 不設（OpenAI） | 內部的回答服務 |
| `ANSWER_MODEL` | gpt-4o | Qwen3.5-9B |
| `ANSWER_EXTRA_BODY` | 不設 | Qwen 建議的抽字設定、關掉思考模式（036） |
| `ANSWER_TIMEOUT` | 15 秒 | 45 秒 |
| `OPENAI_API_KEY` | 要 | 不用 |

- 本機的服務用 vLLM 架，呼叫方式跟 OpenAI 一樣，所以程式只換網址，不用另外寫一套
- 公開展示版什麼設定都不用改，網站不受影響
- 自己架的模型記 0 元（GPU、電費另外算）。只有設定了網址才記 0：用 OpenAI 時模型名字打錯，算錢那一步會報錯，不會默默記成 0
- **問題前面要加任務說明**：Qwen3-Embedding 轉「問題」時要加一段固定的說明，轉文件段落時不加。035 比較模型時就是這樣用的，線上要一模一樣，不然搜到的段落會變差，而且不會報錯

### 二、轉向量也用 vLLM 架，跟回答模型共用一張 GPU

| | 用 vLLM、共用 GPU（採用） | 用 CPU 跑 |
|---|---|---|
| 速度 | 快 | 問題還好（約 0.2 秒），但上傳文件時要轉很多段，比較慢 |
| 部署 | 兩個模型同一套工具、同一種呼叫方式 | 要另外一種工具 |
| 代價 | 回答模型少用約 2GB 的 GPU 記憶體 | 不佔 GPU |

### 三、向量欄位的維度從設定讀

OpenAI 的向量有 1536 個數字，Qwen3-Embedding 有 1024 個，資料庫的向量欄位要一樣。

- 新的 migration（`e5a1b7c9d2f4`）把欄位改成設定的維度：公開展示版本來就是 1536，什麼都不做；企業內部版是全新的資料庫，表還是空的，直接改成 1024
- 表裡已經有向量的話**拒絕修改**並說明原因：舊的向量是別的模型轉的，要全部重新轉
- 在本機的臨時資料庫實際跑過三種情況：1536 不變、1024 改成功、已有向量時拒絕
- 不採用「兩版都統一成 1024」：要改線上的資料庫、所有文件重新轉向量，還要重新量檢索有沒有變差

### 四、回答的等待上限可以設定

本機的 Qwen 比 OpenAI 慢：036 重量時，每題回答 p50 4 秒、p90 10 秒、p99 28 秒、最慢 40 秒。照 OpenAI 的 15 秒上限，約 4% 的問題會失敗，所以企業內部版設成 45 秒。整個問答的時間上限（50 秒）不變。

## 代價

- 兩個模型擠一張 3090，回答模型可以用的記憶體變少
- 換轉向量模型時，問題前面的任務說明要跟著換；換錯不會報錯，只會搜得比較差，所以每次換都要先跑一次只比檢索的評估
- 「搜尋前規劃」（028）是評估工具，還是用 OpenAI 的 gpt-4o-mini；企業內部版沒開，不影響
