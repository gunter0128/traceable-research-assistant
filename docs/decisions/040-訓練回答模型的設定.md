# 040：訓練回答模型的設定

日期：2026-10-27

## 背景

039 產生了合格的示範答案。接下來要在實驗室的 RTX 3090（24GB）上訓練 Qwen3.5-9B 的 adapter，讓它不思考也能照理想回答的寫法回答（038）。要先決定怎麼訓練、怎麼確認有變好、怎麼上線、怎麼記錄。

## 決定

### 一、bf16 LoRA，不用 QLoRA

原本打算用 QLoRA（底模壓成 4-bit），記憶體最寬裕。但 Unsloth 的 Qwen3.5 訓練說明寫明不建議：Qwen3.5 壓成 4-bit 後跟原本的差異比一般模型大，不管大小。而且訓練時看到的是 4-bit 的底模，上線合併進沒壓縮的底模，兩邊會有落差。

所以底模維持 bf16、凍結，只訓練 adapter。Unsloth 列的 9B 約 22GB，3090 很緊，省記憶體的做法：

| 做法 | 省什麼 |
|---|---|
| 看圖的部分放 CPU | 只回答文字，用不到；約 1GB |
| loss 只算回答的部分，模型只算最後那一百多個位置的預測 | 字典有 24 萬多個字，整段 3,000 多個 token 都算要好幾 GB |
| 重算換記憶體（gradient checkpointing） | 往前算時不留每層的中間結果，往回算時再算一次；比較慢 |

放不放得下要試跑才知道；放不下再回來討論。

### 二、設定照 Unsloth 的 Qwen3.5 範例，不搜尋

| 設定 | 值 |
|---|---|
| adapter | rank 16、alpha 16、dropout 0 |
| 掛在哪 | 語言模型的完整注意力層（每 4 層 1 層，q/k/v/o）和每一層 MLP（gate/up/down） |
| learning rate | 2e-4；前 10% 的步數從 0 升上來，之後直線降到 0 |
| 輪數 | 3 輪 |
| 一次更新 | 8 筆（3090 一次只放得下 1 筆，累積 8 筆才更新） |
| 格式 | 跟線上一樣：Qwen 的對話格式、關掉思考模式，輸入是線上的回答原則 + 段落 + 題目 |
| loss | 只算示範答案和結束符號；輸入是給它讀的 |

不搜尋 learning rate 這些設定：每多一組要多考一次試、多花評審費。這次要回答的是「資料量夠不夠」，所以只比資料量；loss 曲線看起來有問題才調。

### 三、資料怎麼分

| | |
|---|---|
| 驗證集 | 每種題型各隨機抽 10%，不拿來訓練。每訓練完一輪算一次驗證集的 loss，存下最好的那一輪 |
| 學習曲線 | 剩下的照題型比例排成一列，取前 50、前 100、全部：50 ⊂ 100 ⊂ 全部、題型比例都差不多，差別只在資料量 |
| 三個版本都一樣 | 都是 3 輪：資料少的更新次數也少，這就是資料量的差別 |

驗證集的 loss 只看「有沒有學到示範答案的寫法、有沒有過度擬合」，不花錢。好不好用還是要看考卷：考卷是另外兩套文件（企業、勞動法規），量的是換了文件還做不做得到。

### 四、上線：先合併再給 vLLM

有人回報 vLLM 直接掛 adapter，在 Qwen3.5 的架構上不會生效（不報錯，但回答跟沒掛一樣）。只有一個人的回報，但如果是真的，考出來的分數會是假的，所以改成先合併：每個掛了 adapter 的權重 W 改成 W + (alpha / r) × B × A，存成一份完整的模型給 vLLM 載入（`train/merge_adapter.py`）。

確認合併沒做錯：合併後的模型在驗證集上的 loss，要跟訓練時最好的那輪一樣（`train_adapter.py --eval-only`）。

### 五、記錄：MLflow，放在實驗室

每次訓練記下設定、訓練資料的版本（檔案的 sha256）、用了哪幾筆、loss 曲線、產出的 adapter。記錄存在實驗室的檔案裡，不送到外面。合併後的模型約 19GB，是考試用的中間產物，考完就刪；adapter 留在 MLflow，要再用時重新合併。

### 六、環境

訓練用的環境跟 vLLM 的分開：torch 裝跟 vLLM 同一版，其他套件列在 `train/requirements-train.txt`，裝好後固定版本。

### 七、流程

1. 試跑：最長的 16 筆訓練 2 步，看記憶體、一筆幾秒、格式對不對；再試合併、用 vLLM 載入
2. 訓練 50、100、全部三個版本
3. 每個版本：合併 → 確認驗證集 loss → vLLM 載入 → 考兩套考卷的練習題，跟沒訓練的比
4. 最好的版本考最後的門檻（038）

## 代價

- 3090 放 bf16 的 9B 很緊，可能放不下
- 設定沒有搜尋，不一定是最適合這批資料的
- 驗證集跟訓練資料來自同一批臺北市政府的規章，只能看出有沒有學到寫法；換文件的效果要看考卷
- 每個版本要存一份約 19GB 的完整模型，換版本時 vLLM 要重開
- 「vLLM 直接掛 adapter 不會生效」沒有自己驗證過；合併比較保險，但如果其實會生效，就多花了合併的時間和空間
